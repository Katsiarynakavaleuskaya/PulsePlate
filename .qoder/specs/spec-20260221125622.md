# Adaptation Plan: BMI-App Orchestration System

## Overview

This plan documents my understanding of and adaptation to the BMI-App (PulsePlate) multi-agent orchestration system for autonomous development workflows.

---

## 1. Key System Understanding

### Coordinator-First Rule (Hard)
- **Every task MUST start with agent-coordinator** for analysis and routing
- Coordinator is the single decision authority and owns final synthesis
- Definition of "task": any work affecting code, docs, architecture, security, or process

### Pre-flight Checklist (Mandatory)
Before any task execution:
1. Load root `AGENTS.md` + `RUNBOOK_AGENT.md`
2. Load affected module `AGENTS.md` files
3. Check relevant contract docs (API/schema/tier changes)
4. Understand required quality gates
5. Identify primary + secondary agents, map dependencies

### Quality Gates (Non-negotiable)
```bash
make verify   # lint → typecheck → test-fast → diff-cov ≥97%
```
- Never claim "mergeable" without `make verify` evidence
- CI red = PR does not exist; fix before any other work

## 3. Backend Engineering Principles

**Business logic in `core/`**, adapters/wrappers in `app/`:
- Never move domain logic from `core/` into routers
- Never introduce import-time side effects

**Test Conventions:**
- ≥97% coverage (total + diff)
- No mocking `builtins.__import__` or `builtins.float`
- No `sys.modules` mutations
- xdist isolation: each worker gets unique SQLite path

## 5. My Adaptation Protocol

### For Any New Task:

1. **Pre-flight (always):**
   - Load `AGENTS.md` → understand invariants + hard rules
   - Check `RUNBOOK_AGENT.md` → operational procedures
   - Load affected module docs (`app/AGENTS.md`, `core/AGENTS.md`, etc.)

2. **Task Analysis:**
   - Identify domain(s): backend, frontend, testing, security, design
   - Check `docs/roadmap/BACKLOG_LEDGER.md` for related items
   - Determine if task requires multi-agent coordination

3. **Execution:**
   - Follow canonical workflow: `docs/orchestration/workflow.md`
   - Use templates when applicable
   - Record any deferred work in `BACKLOG_LEDGER.md`

4. **Quality Verification:**
   ```bash
   make lint          # Code style
   make typecheck     # mypy
   make test-fast     # Deterministic smoke
   make diff-cov      # Coverage ≥97%
   ```

5. **PR Protocol:**
   - Include `## Discussion Thread Pass` + `## Merge Readiness` sections
   - Run `pre-commit run --all-files` before push
   - Never force-push; use new commits or cherry-pick to fresh branch
