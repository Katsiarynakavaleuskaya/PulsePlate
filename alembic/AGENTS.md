# Agent instructions (scope: alembic/ and subdirectories)

## Scope and layout
- This AGENTS.md applies to: `alembic/` and below.
- Key files: `alembic.ini`, `alembic/versions/`.

## Commands (run from repo root)
- Create migration: `alembic revision -m "<message>"` (add `--autogenerate` if configured).
- Upgrade: `alembic upgrade head`
- Downgrade: `alembic downgrade -1`

## Conventions
- Keep migrations deterministic and reversible.
- Align schema changes with SQLAlchemy models and tests.
- Confirm target DB (SQLite/Postgres) before running destructive migrations.

- **Single Base rule**: Alembic must target the canonical SQLAlchemy metadata from `core.db.Base`.
  Never create/import a second `Base` (no `declarative_base()` in models).
- **No dynamic import hacks**: Do not use `spec_from_file_location`, `exec_module`,
  or sys.path hacks to load the app/models for migrations. If env.py needs imports,
  use normal package imports only.
- **Migration-data ownership**: `alembic/` is ScriptDirectory data and must not
  define a top-level regular-package carrier. Never add `alembic/__init__.py`;
  the installed regular Alembic distribution must uniquely own `alembic`,
  `alembic.config`, `alembic.context`, and `alembic.op` even when the repository
  root is on `PYTHONPATH`.
- **Declarative repository imports**: standalone migration commands receive the
  repository root through `alembic.ini` (`prepend_sys_path = %(here)s` and
  `path_separator = os`). Do not restore imperative path mutation in `env.py`.
- **Single-head graph**: the migration tree must resolve through
  `ScriptDirectory` and expose exactly one non-empty head.
- **No reload patterns**: never use `importlib.reload`, `Base.metadata.clear()`,
  or similar in migration context; it can desync mapper/metadata and break autogenerate.

## Autogenerate sanity checks

- PostgreSQL autogenerate must keep type and server-default comparison enabled.
  Custom default handling is limited to exact semantic equality for PostgreSQL
  JSON/JSONB values; unequal, malformed, non-JSON, and unsupported values remain
  visible or fail closed. Blanket JSON suppression is forbidden.
- Reflection of `public.user_knowledge.embedding` must resolve its exact vector
  type and dimension. An unrecognized vector type or `NullType` is terminal and
  must not be ignored or treated as equality.
- For a finite classified reconciliation, model-description drift is fixed in
  canonical model declarations and physical schema drift may use at most one
  deterministic reversible forward revision. Never rewrite historical revisions
  or hide unknown operations with broad include, type, or default filters.
- Any additional or unclassified autogenerate operation stops the reconciliation
  and requires a new bounded classification before implementation continues.
- Raw PostgreSQL autogenerate comparison must run before any object admission.
  Admission is limited to the four exact reviewed public migration-only roots:
  `foods`, `pulseplate_migration_ownership`, `restaurant_chains`, and
  `restaurant_menu_items`.
- Those roots require an independent physical descriptor validation before the
  admitted comparison may be evaluated. The resulting PASS is bounded to this
  exact-head admission and is not universal PostgreSQL completeness, production
  parity, deployment safety, or merge authority.

Before committing an autogenerated revision:

```bash
# Ensure metadata comes from the single canonical Base
python - <<'PY'
import core.db
print("Base:", core.db.Base)
print("tables:", len(core.db.Base.metadata.tables))
PY
```

Then inspect generated migration:

- No accidental drops/creates due to import-order issues
- Reversible downgrade exists
- SQLite/Postgres compatibility respected (types, constraints)
