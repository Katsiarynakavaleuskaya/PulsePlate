# FitChef Claim Evidence Eval v1

<!-- markdownlint-disable MD013 -->

This contract evaluates the **final** `balanced_reframe` of the internal Distortion Simulator against the exact synthetic context and the full sanitized source snapshot admitted to its prompt. It measures agreement between a blind candidate assessor and an independently prepared, human-accepted reference. A source link, retrieval score, NOOS-1A structural pass, or this report's process exit does not establish semantic support, causal truth, clinical safety, product improvement, or permission to change an answer.

## Corpus and collection

The private manifest has 24 unique canonical scenario IDs: 16 development and 8 holdout; eight each in Russian, English, and Spanish. Six families have four scenarios each: cautious explanation, causal overclaim, contradicting source, irrelevant citation, context/time mismatch, and absent evidence. Holdout allocation is two causal-overclaim and two absent-evidence cases, with one each from the other four families. The holdout and all reference labels stay outside Git and outside the implementation context. Twelve manually authored development controls, one acceptable and one unacceptable behavior per family, are tracked separately from the 24 real Sonar scenarios and cannot be reported as fresh provider output. An acceptable absent-evidence control may state only that the supplied snapshot lacks support; it does not claim external completeness. Replays and mocked integrations carry their own provenance.

The opt-in collector calls `app.services.fitchef_runtime.run_distortion_simulator_task` with controlled synthetic RAG chunks, the existing `providers.perplexity.PerplexityProvider`, `model=sonar`, `max_tokens=1024`, and `web_search_options.disable_search=true` in the actual request body. Before that internal call, it checks the live structured-coach feature flag and normal `auto-safe` execution mode, applies the route's shared AI-input guard to every synthetic user field, screens controlled source text as AI-facing input, and carries the canonical `POST /api/v1/pro/fitchef/explain` endpoint identity. It observes the original provider message, final result, exact admitted sanitized source occurrences, and invocation of the real balanced-reframe fallback. It forwards to the original fallback, including the silent empty-field path. A controlled retrieval failure or mismatch with the admitted source snapshot invalidates the case. Each case records input provenance and final field origin separately. A missing warning cannot prove model authorship; only a canonical provider field matching the final answer earns `provider`, while an unproven transformation is `unknown`. This remains an internal controlled run; HTTP tier, rate-limit, and response-envelope parity need separate route tests.

The input language is a scenario property; observed answer language must be examined in the reference review, not assumed from input. The current prompt and template fallback may be English even for Spanish input. This corpus measures that behavior; it does not establish a Spanish FitChef API or health/therapy safety claim. No real user data belongs in the manifest or outputs.

The collector requires a committed, tracked-clean checkout, an empty owner-owned mode-0700 output directory, and private `PERPLEXITY_API_KEY` and `NOOS_EVAL_FITCHEF_API_KEY` environment values. Every run binds the commit SHA plus executing collector, evaluator, runtime, fallback and provider-module byte hashes; drift during collection stops the run. The FitChef key must be a newly generated synthetic `noos-eval-...` key listed in `PRO_API_KEYS`, never a customer key. The local run requires `APP_ENV=development`, `SUBSCRIPTION_DB_ENABLED=false`, a private absolute SQLite `DATABASE_URL`, `PRO_LLM_INSIGHT_REQUESTS_PER_MONTH` of at least 24, `SERVER_SALT`, `AGENT_CONTROL_AUDIT_SIGNING_KEY`, a private absolute `AGENT_CONTROL_AUDIT_LOG_PATH`, `FEATURE_FITCHEF_STRUCTURED_COACH=true`, and `FITCHEF_STRUCTURED_COACH_EXECUTION_MODE=auto-safe`. Initialize the quota table in that isolated SQLite DB using the normal repo schema path before collection. These are run-local settings; the collector adds no startup environment variable. Do not place keys, salts, or audit secrets in manifest, pricing evidence, logs, chat, or Git. Existing runtime policy and monthly quota gates remain active. Run the paid collector only after verifying the selected model, [Perplexity pricing](https://docs.perplexity.ai/docs/getting-started/pricing), request parameters, and a conservative price upper bound for the 32 KiB request/1024-token cap. Record that check in a private one-line `fitchef_pricing_evidence.v1` JSONL record. The collector requires its bound `model=sonar`, `max_request_bytes=32768`, `max_tokens=1024`, a primary documentation URL, verification time, and a maximum cost per physical attempt no greater than US$0.15. This metadata records an operator check; it cannot authenticate a provider price.

Every HTTPX send attempt, including OpenAI SDK and Tenacity retries, writes a private US$0.15 reservation **before** transport. The 33rd attempt is rejected before network. At most 32 attempts reserve US$4.80 under the US$5 owner cap. If Sonar returns numeric `usage.cost.total_cost` above the per-attempt reserve, the collector stops before another send and preserves the overrun in its private receipt. A case cost is known only when exactly one physical attempt returned its cost; prior uncertain retries, absent cost, and timeout keep the whole case unknown with reservations retained. The collector suppresses Python logs during the scoped runtime call because upstream exceptions can contain sensitive prompt or provider text, then restores logging. It prints only a bounded error type. Do not rerun a case for a preferred answer or start another budget directory to evade the cap. Each completed case is written privately; terminal failure or cancellation writes a private no-replace status receipt with completed and missing IDs, manifest fingerprint, attempt count and reserve, with no exception text. Partial results and reservations remain for reconciliation. No semantic retries are added.

## Annotation rubric

Annotate each distinct assertive proposition in the final answer with exact Unicode code-point `[start,end)` indices and the verbatim quote. Minimal pure empathy without a proposition is assessed under answer quality and wellness wording, outside the evidence matrix. Use one claim type from `core.judgment.ClaimType`: `fact`, `source_grounded_summary`, `inference`, `recommendation`, `speculation`, or `emotional_framing`. Use one `EvidenceMode`: `direct_source`, `cross_source_synthesis`, `deterministic_verifier`, `heuristic`, or `none`. The mode describes the proposed evidence route and does not itself grant support.

Assign exactly one `SupportStatus` relative to the supplied snapshot: `supported` (direct entailment at matching subject, population, time and scope), `partially_supported` (a material but qualified or incomplete match), `unsupported` (no adequate supplied support), or `contradicted` (supplied evidence conflicts). A citation or source ID alone is never entailment. Explicit negation, changed population, stale time, and conflicting passages must be considered. Cite exact source occurrence ordinals and verbatim source spans in `source_refs`, or use an empty list and explain the absence in `rationale`. Do not infer external completeness: the reference is an owner-accepted interpretation of the frozen supplied snapshot.

Separately assess answer usefulness, confidence proportional to evidence, language fit, and wellness-only boundary in the private reference review. Record a concrete reason and relevant answer/source quote for each concern. These subject-matter judgments do not become an automated semantic classifier or a runtime policy.

## Blind handoff and comparison

`prepare` creates one allowlisted packet per case with only an opaque case ID, material fingerprint, final answer, scenario context, requested language, opaque per-case source references with full content, and rubric hash. It excludes case ID, source filenames/chunk IDs/scores, split, family, input provenance, field origin, raw provider text, expected labels, reference, warnings, and results. The owner freezes the reference and accepts its exact byte hash **before** candidate judgments are revealed. Record that event in a private `fitchef_claim_reference_acceptance.v1` JSONL record (`accepted_by=OWNER`). The receipt records the owner's decision but is not a cryptographic signature; blind assessor isolation must be separately verified. A normal subagent with inherited history is not blind.

The candidate and reference use separate `fitchef_claim_annotation.v1` JSONL files, one row per opaque case ID, with `material_fingerprint`, `abstain`, `claims`, and case-level `answer_quality`. Each claim requires `start`, `end`, `quote`, `claim_type`, `support_status`, `evidence_mode`, `source_refs`, and nonempty `rationale`. A `source_ref` uses the packet's opaque `source-N` token plus exact source span and quote. Candidate `support_status=abstain` locates a claim whose evidence status is unjudged; a whole-case `abstain=true` has no claims and `answer_quality=null`. Reference claims and cases cannot abstain. A missing candidate row or absent span is counted separately from either abstention. The validator rejects duplicate keys/rows/claims, unknown refs, bad spans/quotes, stale fingerprints, extra fields, malformed types, unsafe paths, and partial publication. Changed answer, context, source bytes, run identity/configuration, or rubric bytes invalidate the old annotation.

For each judged case, `answer_quality` has exact fields `observed_language` (`ru`, `en`, `es`, `mixed`, `other`, `unknown`), `language_fit` (`match`, `mismatch`, `unknown`), `usefulness`, `confidence_proportionality`, and `wellness_wording` (each `appropriate`, `mixed`, `inappropriate`, `unknown`), plus one concise rationale and an exact substring quote from the final answer. The observed language and requested language must agree with the language-fit label for the three named languages. These are separately supplied judgments; the evaluator does not derive them from text or use them as evidence-support labels.

Matching is exact by opaque case ID, material fingerprint, and answer span/quote. Candidate and reference must be different filesystem objects. Different boundaries remain unmatched; no fuzzy alignment or inferred verdict is used. The 4×4 confusion matrix covers only matched substantive semantic labels. The broad false-acceptance numerator counts candidate `supported` or `partially_supported` against reference `unsupported` or `contradicted`; its denominator is all matched reference negatives. A severe subset counts candidate `supported` against those negatives. False rejection counts candidate negative against matched reference positive. Coverage uses **all reference claims** as denominator, including candidate omissions and abstentions. The report exposes unmatched candidate claims, reference omissions, whole-case and per-claim abstentions, missing rows, reference answer-quality counts, candidate/reference quality agreement, observed-language counts, language-mismatch case IDs, split/family/language/provenance slices, reservation and known/unknown cost. The report fingerprint binds canonical validated cases, candidate, accepted reference, rubric and any supplied NOOS-1A input digests; it is content identity, not proof of semantic truth. Every zero denominator is `not_measured`. Repeated variants cannot increase the independent canonical-case count. A wellness-wording label is a bounded review judgment, never a clinical safety certificate.

NOOS-1A `parse_snapshot`/`audit_snapshot` may add a separate structural advisory to the report. Its authority and answer-change flags remain false. Report results may be negative and still be valid measurements.

## Local commands and completion boundary

Run from the repository root with the repo Python resolver and private paths; `OUTPUT_DIR` must exist as mode 0700 before collection:

```bash
python -m scripts.evals.collect_fitchef_answers --manifest PRIVATE_MANIFEST.jsonl --rubric docs/evals/FITCHEF_CLAIM_EVIDENCE_EVAL_V1.md --pricing-evidence PRIVATE_PRICING.jsonl --output-dir OUTPUT_DIR
python -m scripts.evals.fitchef_claim_assurance_eval prepare --cases OUTPUT_DIR/cases.jsonl --rubric docs/evals/FITCHEF_CLAIM_EVIDENCE_EVAL_V1.md --output PRIVATE_PACKET.jsonl
python -m scripts.evals.fitchef_claim_assurance_eval validate --cases OUTPUT_DIR/cases.jsonl --rubric docs/evals/FITCHEF_CLAIM_EVIDENCE_EVAL_V1.md --packet PRIVATE_PACKET.jsonl --candidate PRIVATE_CANDIDATE.jsonl --reference PRIVATE_REFERENCE.jsonl --reference-acceptance PRIVATE_ACCEPTANCE.jsonl
python -m scripts.evals.fitchef_claim_assurance_eval report --cases OUTPUT_DIR/cases.jsonl --rubric docs/evals/FITCHEF_CLAIM_EVIDENCE_EVAL_V1.md --packet PRIVATE_PACKET.jsonl --candidate PRIVATE_CANDIDATE.jsonl --reference PRIVATE_REFERENCE.jsonl --reference-acceptance PRIVATE_ACCEPTANCE.jsonl --output PRIVATE_REPORT.json
```

The script's report is a measurement artifact. Completion requires all 24 observed cases, owner-accepted reference, verified tool-disabled blind Codex execution, exact material bindings, focused local and current-head CI gates, and normal PR review/readiness. This PR changes no public HTTP DTO/OpenAPI, FitChef product runtime, Graph/OCW serving, semantic cache, entitlement, or knowledge promotion. Rollback is a revert of the offline scripts, tests, fixture, and contract; private historical results remain evidence, not product data.
